# WhiteSoft — 带 PDF 导入与 .note 支持的本地白板

**WhiteSoft** 是一个复刻 **Microsoft Whiteboard（Windows 本地版）** 的本地应用，
运行在浏览器里、由本机 Node 进程提供服务。

它的两个核心能力，正好对应你手上的那两个文件：

* **导入 PDF**：一个 n 页的 PDF 会变成 **n 张画纸**，每张画纸用对应的 PDF 页作为背景，
  可以在右下角的**页码输入框**里输入页码直接跳转。
* **打开 `.note`**：直接读取 Microsoft Whiteboard 本地版保存的 `.note` 压缩包，把每一张
  画纸上的墨迹、荧光笔、直线、矩形、椭圆、箭头、折线、图片、文本，以及 PDF 背景，
  **按原始坐标忠实还原**；修改后还能再存回 `.note`。

## 快速开始

在终端里运行 `app/` 里的启动脚本即可：

```bash
./app/whitesoft.sh
```

（脚本可以放在任何地方调用，它会自己定位到 `app/`；工作区默认取 `app/` 的上一级目录。）

它会检查 Node 版本、确认端口可用、列出工作区里的白板、打印界面地址，然后启动服务：

```
WhiteSoft — 本地白板
──────────────────────────────────────────────
界面地址 : http://127.0.0.1:8787/
工作区   : /path/to/workspace
发现白板 : Al-jabr-1.note, Al-jabr-2.note
停止服务 : Ctrl+C
──────────────────────────────────────────────
```

然后浏览器打开 **http://127.0.0.1:8787/**（加 `--open` 可以自动打开）。

常用参数：

```bash
cd app
./whitesoft.sh --open                 # 启动后自动打开浏览器
./whitesoft.sh --port 9000            # 换端口
./whitesoft.sh --auto-port            # 端口被占用时自动顺延
./whitesoft.sh --root ~/my-boards     # 指定工作区目录
./whitesoft.sh --help                 # 查看全部选项
```

（仓库根目录的 `start.sh` 是等价的兼容入口，内容只是转发到 `app/whitesoft.sh`。）

也可以绕过脚本直接启动服务端：

```bash
cd app && node server.mjs --port 8787 --host 127.0.0.1 --root ..
```

* `--port` 端口（默认 8787，也可用环境变量 `PORT`）
* `--host` 监听地址（默认 127.0.0.1）
* `--root` 工作区根目录（默认是 `app/` 的上一级，也就是存放 `.note` 的目录）。
  标题栏的“打开”对话框会列出该目录下的 `.note` / `.pdf` 文件。

> 服务端**零运行时依赖**，只用 Node 内置模块；PDF 渲染（pdf.js）、ZIP 读写
> （fflate）都已放在 `app/public/vendor/` 里，离线可用。

### 第一次使用

1. 点标题栏的 **导入 PDF**（或把 PDF 拖进窗口）→ 生成 n 张画纸。
2. 用左侧工具在画纸上批注；右下角 `‹ [页码] / n ›` 可以跳到任意画纸。
3. `Ctrl+S` 保存为 `.note`，得到的文件可以直接用 Microsoft Whiteboard 打开。

想直接看效果的话，点 **打开**，选择工作区里的 `Al-jabr-1.note` —— 446 张画纸、
1428 张图片、32 万条墨迹点会完整还原。

## `.note` 格式（反向工程结果）

`.note` 就是一个普通 ZIP：

```
manifest.json                     文档元信息 + 画纸顺序
Pages/page<N>.json                每张画纸一个文件
Resources/Images/<guid>.png       所有粘贴 / 插入的位图
Resources/Document/<name>.pdf     导入的 PDF 原件
```

### manifest.json

```json
{
  "id": "26388044-80ca-4583-9f33-382a045635a9",
  "version": "1.0.0",
  "screenWidthPixels": 2880,
  "screenHeightPixels": 1920,
  "screenScale": 2,
  "pages": [{ "fileName": "page1.json" }, ...],
  "currentPage": 163,
  "backgroundColor": "#FFFFFFFF",
  "createTime": "2026-09-18 20:31:00",
  "document": { "fileName": "Al-jabr-1.pdf" }
}
```

### 画纸 `Pages/pageN.json`

```json
{
  "elements": [ ... ],
  "scale": 0.8,
  "pdfPages": [{ "pageNumber": 10, "bounds": "143.998,83.1995,1152.0033,1636.0026" }]
}
```

* `bounds` 一律是 `"x,y,w,h"`，**世界坐标**（与元素坐标同一套）。
* `scale` 是导入 PDF 时的缩放级别：**PDF 页的世界宽度 = 视口逻辑宽度 × scale**。
  在本机上视口逻辑宽度是 `screenWidthPixels / screenScale = 2880 / 2 = 1440`，
  所以 `1440 × 0.8 = 1152.0033` —— 与文件里的数值完全吻合。PDF 页水平居中
  （`x = (1440 − 1152) / 2 = 143.998`）。
* 以 `Al-jabr-2.note` 验证：`scale = 0.997743` → `1440 × 0.997743 = 1436.75`，
  文件里正是 `1436.7428`。

### 元素类型

| 数值 | 含义 | 字段 |
|---|---|---|
| `100001` | 手写墨迹 | `stroke` `width` `inks:[{x,y,pr}]`，`pr` 为压感 0–1 |
| `100005` | 荧光笔 | `stroke`(带透明度) `width` `closed:false` `points:[{point:"x,y"}]` |
| `200002` | 直线 | `points`（2 点，可带 `dash:true`） |
| `200003` | 矩形 | `points`（4 点，`closed:true`） |
| `200004` | 椭圆 | `points`（4 点 = 上/右/下/左，`closed:true`） |
| `200015` | 箭头 | `points`（4 点 = 起点/终点/箭头两角） |
| `200017` | 折线 | 任意点数，可带 `dash` |
| `300001` | 图片 | `bounds` `rotation` `fileName` |
| `300002` | 文本 | `bounds` `fontSize` `text` `textColor` |

画笔颜色是 .NET 的 `#AARRGGBB`；荧光笔的 `5A` 前缀就是它 ~35% 的透明度。
`pr` 是压感：渲染时按 `width/2` 做变宽缎带，笔迹因此有自然的粗细变化。

### 本克隆新增的类型（MS Whiteboard 不会用到，但格式兼容）

| 数值 | 含义 |
|---|---|
| `200005/6/7/8/9/10/11` | 三角形 / 菱形 / 五边形 / 六边形 / 五角星 / 平行四边形 / 块状箭头 |
| `200016` | 双箭头 |
| `400001` | 便签 |
| `400002` | 表格 |
| `400003` | 反应（emoji） |

另外 `locked` / `rounded` / `inkGradient` / `arrow` / `textAlign` 等是可选扩展字段，
保存后依然是合法 JSON，读回时原样保留。

## 功能

**墨迹**：**3 支可分别自定义的笔**（`Alt+1/2/3` 切换，各有 15 色 + 彩虹/极光渐变笔、
粗细 1–20 连续滑块、不透明度、无/单/双箭头）、荧光笔（15 色、半透明、
**「直线绘制」开关** —— 开启后像直线工具一样拉出笔直高亮）、
激光笔（不落墨、自动淡出）、橡皮擦（整笔擦除）、`Shift` 画直线。

**高亮端点**：凡是**直线**高亮（两点，或多点但完全共线）都画成「跑道形」——
矩形高亮带 + 两端半圆。这不只对新画的生效：**打开原版 `.note` 时，
里面用直线绘制划的高亮也会以半圆端点渲染**（Al-jabr-1 的 2172 条高亮全部是两点直线，
所以整本都会变成圆头）。自由手绘的弯曲高亮仍是平头。
不想要这个效果可以在 设置 里关掉「高亮直线显示半圆端点」。

**直尺**：点工具栏尺子图标或按 `R` 显示。直尺悬在画布之上，**任何工具下都能直接抓住**：
拖尺身移动、拖右端手柄旋转、悬停时滚滚轮微调角度；沿尺边画线（含荧光笔）自动吸附成直线，
`Shift` 可吸附到 15° 整数倍。

**对象**：形状（正方形 / 圆 / 三角形 / 五边形 / 块状箭头 / 平行四边形 / 菱形 / 圆角矩形 +
虚线 / 直线 / 单箭头 / 双箭头，可填充、可虚线）、文本框、便签（12 色）、表格、
图片（插入 / 粘贴 / 缩放 / 旋转）、反应（8 个 emoji）。

**选择与编辑**：套索选择、矩形框选、点选、`Shift` 加选、八向缩放手柄、旋转手柄、
层序调整、锁定/解锁、对象吸附对齐参考线、墨迹转形状（Beautify）、复制粘贴再制、
方向键微移、`Alt+方向键` 旋转。

**框选手势（套索 / 矩形框选）**：按下就进入**虚线框选流程**——
拖动过程中画面上会实时画出**虚线矩形 / 虚线套索**并把区域淡淡着色，
同时**忽略按下的那个对象**（不会顺手把它拖走、也不会提前选中）；
松手时才根据最终区域判定选中了哪些东西。

- 起点落在**已选中的对象**上时，这一次是"移动"（这样选中之后才拖得动）。
- 原地点一下（没有拖动）等同于点选：选中指针下的那个对象。
- 拖动手柄（缩放 / 旋转）不受影响，一按即生效。

**图片等比缩放**：图片（和反应）无论拖角手柄还是边手柄，都保持长宽比不变。

**所选操作栏**：选中任何对象后，选区**下方**浮出一条操作栏，包含
改变颜色、复制到上一页 / 下一页 / 指定页码、复制、再制、删除、置于顶层 / 底层 /
移到图层最底层。拖动时会自动隐藏，不会挡住手势；误关之后可以点工具栏的「操作栏」按钮恢复。
- **复制到任意页**：把选中的对象原坐标复制到目标画纸，原页保留；可撤销。
- **改变颜色**：按所选内容自动切换色板（便签用便签色板、文本用文字色板、
  荧光笔用高亮色板，其余用笔的色板）；图片和反应不可改色，会给出提示。
- **移到图层最底层**：解决图片盖住批注的问题。

**删除**：`Delete` / `Backspace` 删除全部选中对象（墨迹、形状、文本、便签、表格、图片、反应），
工具栏垃圾桶按钮、`⋯ 更多` 菜单、**右键菜单**（剪切 / 复制 / 再制 / 置顶 / 置底 / 锁定 /
替代文本 / 删除）都能触发；删除可整体撤销并恢复原来的层序与选中状态。
空白处右键是另一套菜单（粘贴 / 全选 / 解锁全部 / 适应页面 / 清空画纸）。

**视图**：无限画布、**移动画布工具（手形，`G`）**、空格 + 拖动、中键拖动、
滚轮平移、`Ctrl+滚轮` 以光标为中心缩放、双指缩放、
适应宽度 / 显示整页、**全屏（F11）**、背景（无 / 方格 / 横线 / 点阵 + 画布颜色）。

**比例是全局的**：整个白板只有**一个缩放比例**，在第一页从 80% 调到 100%，
翻到第 50 页、第 200 页也还是 100%；翻页只改变滚动位置（每页顶部对齐），不改变比例。
「适应宽度 / 显示整页」算出的比例同样会成为全白板的比例。

**底栏比例可直接输入**：在右下角的比例框里输入 `137`、`42.5%`、`250` 回车即跳到该比例，
留空回车回到 100%，非法输入不生效。**新建 / 打开白板的默认比例是 80%**，
可以在 设置 →「新建 / 打开白板时的默认比例」里改成 50% / 80% / 100% / 125% / 150%。

**页面**：页面面板（实时缩略图、拖拽排序、复制、删除）、新建画纸、
**右下角页码输入框跳转**、`PageUp/PageDown` 翻页。

**文件**：导入 PDF（n 页 → n 张画纸，版式为一屏宽，即在 100% 时正好铺满窗口宽度）、
打开 `.note`、保存 / 另存为 `.note`、导出 PNG / PDF / Zip(HTML+JSON)、
拖放 `.note` 或 `.pdf` 到窗口打开。
**白板有未保存更改时，打开其他 `.note`、导入 PDF 或新建白板都会先弹出确认框**
（取消 / 放弃更改 / 保存并继续）。

**快捷键区分大小写**：小写字母是工具（`N` = 便签），大写字母是独立绑定（`Shift+N` = 新建白板），
所以 `Shift+N` 不会误触发便签工具。

**其他**：完整撤销重做、512 级历史、中文输入法友好的文本编辑、
**替代文本（Alt text）**、工具栏位置可切换（底部 / 顶部 / 左侧 / 右侧）。

## 测试

```bash
cd app
node server.mjs &                 # 测试需要服务在 8787 端口
node test/e2e.mjs                 # 51 项端到端功能测试
node test/round2.mjs              # 32 项交互细节测试（表格编辑、手柄、直尺、手势…）
node test/round3.mjs              # 46 项新功能测试（即时重绘、移动画布、直线高亮…）
node test/round4.mjs              # 28 项交互测试（框选手势与虚线、数字快捷键、操作栏、等比缩放…）
node test/perf.mjs                # 帧率基准（可加 --dpr 2）
node test/strokes.mjs             # 笔迹连续性（沿笔迹中线逐像素检查断点）
node test/visual.mjs --index 167  # 渲染第 168 张画纸并输出 pdftoppm 参考图
node test/thumbs.mjs              # 页面缩略图
```

`test/e2e.mjs` 用 Puppeteer 驱动真实 Chromium，覆盖：两个 `.note` 的加载与还原、
重页面（1751 个元素 / 18.6 万个点）渲染性能、全部绘图工具、直尺约束、
选择变换与撤销、墨迹转形状、页面导航、`.note` 保存回读、PDF 导入、
导入后另存为 `.note`、PNG / Zip 导出。

`test/round2.mjs` 覆盖交互细节：打开对话框、表格单元格编辑、便签缩放与旋转手柄、
复制粘贴与跨页粘贴、滚轮平移 / `Ctrl+滚轮` 缩放 / 空格拖动、直尺移动与旋转与滚轮微调、
四种背景、全部 `Alt+…` 快捷键、三支笔槽、替代文本、剪贴板粘贴图片、拖放提示。

`test/strokes.mjs` 沿每条墨迹的中线逐像素采样，要求 100% 命中——
变宽缎带的几何或填充规则一旦出错就会在笔迹上留下空洞，这项检查能立刻抓到。
覆盖 45% / 80% / 150% 三档缩放、大幅摆动的手写轨迹，以及荧光笔。

## 性能

渲染器做过一轮针对性优化，重页面（1751 个元素 / 18.6 万个点）现在也能跑满帧：

| 优化 | 说明 |
|---|---|
| **世界坐标缓存 + 亚像素切片 blit** | 每帧只把缓存里**可见的那一小块**贴到画布上，绘制开销与视口大小成正比，与缓存留了多少余量无关 |
| **缓存分辨率按 2 的幂吸附** | 连续缩放只在跨越一个八度时才重建，不再每个滚轮事件重建一次 |
| **手势期间延迟重建** | 拖动 / 缩放过程中先复用旧光栅（只是被缩放），松手后再重建，手感不掉帧 |
| **PDF 合成进缓存** | 每帧重新缩放合成一张 1800×2557 的 PDF 位图要约 15ms，现在只在重建时做一次 |
| **Path2D 几何缓存** | 笔迹 / 荧光笔 / 形状的路径按元素缓存（用 WeakMap），重建时直接复用，不再重算 18.6 万个点。注意变宽缎带与端点半圆必须**分成两个路径分别填充**——圆弧永远顺时针，合并进同一个路径会与缎带的反向环绕相消，在笔迹上打出空洞 |
| **不按帧强制排版** | 画布位置改为缓存，不再每个 pointermove 都 `getBoundingClientRect()` |
| **图片加载合并失效** | 同一帧到货的多张图片只触发一次重建，且手势期间延后 |
| **PDF 位图按整八度分档** | 重新栅格化 PDF 很贵，现在只有缩放跨一倍时才重做 |

实测（`node test/perf.mjs`，1600×1000，软件渲染）：

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 每帧绘制耗时（轻页面） | 16.9 ms | **0.1 – 1.2 ms** |
| 每帧绘制耗时（重页面） | 17 – 22 ms | **0.2 – 3.8 ms** |
| 重页面缩放最差帧 | 200 ms | **17 ms** |
| 重页面框选 | 44 fps | **60 fps** |
| 重页面平移 | 43 fps | **60 fps** |

在 `devicePixelRatio = 2` 下渲染器自身仍是亚毫秒级；此时无头浏览器的软件合成会把帧率压到约 30fps，
真实浏览器有 GPU 合成，不会遇到这个上限。

## 已知限制

* **只支持 `.note` 这一种本地格式**。云端 `.whiteboard` 是 OneDrive 的存储格式，
  不是文件格式，无法导入。
* **保存是非破坏性的**：`.note` → `.note` 只重写 `manifest.json` 和 `Pages/*.json`，
  源归档里的**每一个条目都原样搬运**（包括当前没有任何画纸引用的图片），
  所以保存永远不会悄悄丢东西，只会因为新插入的图片而变大。
  350 MB 的白板存回也只需一两秒。写入方式是先写临时文件再原子重命名，
  中途失败不会破坏原文件。
* 从零新建（导入 PDF 后另存）的白板会把 PDF 内嵌进 `.note`，文件大小 ≈ PDF 大小。
* **保存会覆盖 `doc.path` 指向的文件**（也就是你最初打开的那个 `.note`）。
  想保留原件请用标题栏的「导出」旁边的另存为入口，或先把文件复制一份。
* 撤销历史按操作增量记录，上限 512 步。
* 页面缩略图是按需渲染的；快速滚动 400+ 页时缩略图会逐个补齐。
* 这是单人本地应用：没有协作、评论、模板、Bing 图片搜索等联网功能
  （原版这些能力依赖 Microsoft 账号与云服务）。
* 荧光笔的**半圆端点**来自本克隆的渲染规则（直线高亮一律圆头），
  新画的高亮会写一个 `cap: "round"` 标记，原版文件没有这个字段；
  Microsoft Whiteboard 打开时忽略该字段、按平头显示，其余部分不受影响。
* **缩放比例不写进 `.note`**：它只在本次会话内全局生效，重新打开白板会回到默认 80%。
  文件里 `page.scale` 保留原版语义（版式因子 = 页面世界宽度 / 1440）。
